- **Screen-based Architecture**: Each major UI state (Main Menu, Multiplayer Lobby, Pause, Game Over) is implemented as a distinct `Control` or `CanvasLayer` scene with its own controller script (e.g., `main_menu.gd`, `lobby.gd`).
- **Centralized State Management**: UI components rely on the `/root/GlobalSettings` autoload for persistent configuration (language, graphics, volume) and `/root/MultiplayerManager` for network state, reacting to signals like `settings_changed` or `lobby_updated`.
- **Dynamic Resource Preloading**: The main menu integrates with a `/root/ResourcePreloader` to asynchronously load heavy assets and shaders before scene transitions, displaying a dynamic overlay (`_build_load_overlay`) to prevent freezing.
- **In-Game HUD Composition**: The `HUD/` subdirectory contains specialized layers like `hud_game.gd` (health, ammo, subtitles) and `minimap.gd`, which attach to the active player via group signals (`players`) and update in real-time.
- **Signal-Driven Navigation**: Scene changes are triggered via `get_tree().change_scene_to_file()` or managed by external flow controllers (e.g., `MissionFlowPlayer`), while internal UI panels (like Settings) use custom signals (`back_requested`) to maintain decoupling.
